# QazaqDos: учебный MVP

## Что изменено

Исходный стек сохранён: Next.js 15 App Router, React 19, TypeScript, lucide-react и существующие CSS-компоненты. Новый личный кабинет находится в `/learn`. Исследовательское демо, 1000 прежних уроков, диагностика, голосовые функции и учительские страницы остаются на прежних URL. Их данные не смешиваются с новой программой.

Реализованы:

- Supabase email/password signup и login, PKCE callback, подтверждение email по token hash, выход и обработка ошибок. После входа незаполненный профиль направляется на обязательный `/onboarding`.
- Выбор русского/английского языка объяснений и одной из пяти целей, никнейма, аватара и анимаций. Настройки сохраняются в профиле; переключение цели сохраняет предыдущий прогресс.
- Пять курсов, девять разделов по пять уроков, 45 уроков и 225 заданий. Каждое направление содержит минимум два урока. Уровень контента MVP — A1; уровень игрока обозначается отдельно.
- 13 типов заданий: перевод, предложение из слов, пары, пропуск, ситуация, аудирование, ввод через микрофон, карточка, события по порядку, исправление порядка слов, учебный диалог, квиз на время, открытое размышление. Ошибки добавляются в отдельное повторение.
- Два произведения Ыбырая Алтынсарина: «Әке мен бала» и «Асыл шөп». Есть оригинальные краткие пересказы, персонажи, события, словарь, тесты, сортировка и открытые вопросы. Полные тексты не копировались. Справочный источник: https://adebiportal.kz/ru/news/view/stranicka-ucenika-ybyrai-altynsarin__23580.
- Последовательное открытие уроков и разделов, сохранение проверенных ответов, состояния «доступен», «начат», «завершён», «идеально», «заблокирован».
- Dashboard: следующий урок, цель, XP, монеты, уровни, ежедневные задания, достижения, календарь активности и серия. Серия обновляется при завершении урока; календарь и недельные XP используют UTC.
- Награды: 10 XP + 1 монета за верный ответ с первой попытки; 30 XP + 10 монет за урок; идеальный урок +20 XP +5 монет; тест +20 XP; раздел +50 XP +20 монет; исправленная ошибка +5 XP +1 монета; активный день +5 XP +1 монета; новый уровень каждые 200 XP даёт 10 монет. Задания дня имеют собственные награды. Повторный запрос не начисляет награду заново.
- Магазин фиксированных покупок: шарф, тема, рамка и постоянная подсказка первого слова. Никаких платежей, случайных призов и денежных операций.
- Недельные категории Қола / Күміс / Алтын / Гауһар. Рейтинг **демонстрационный**: собственные XP пользователя и явно помеченные вымышленные участники.
- Досша меняет эмоциональные состояния и сопровождает задания. Диалоги используют подготовленные учебные сценарии; внешний генеративный AI не подключён.
- Адаптивная навигация, focus states, клавиатурные кнопки выбора слов, aria-label, loading/error/empty states, уменьшение анимаций через настройки и prefers-reduced-motion.

## Запуск

```bash
npm install
cp .env.example .env.local  # только если .env.local ещё нет
# Указать URL и publishable key Supabase
npm run dev
```

Открыть `/login`. Для автономной проверки нажать «Попробовать без регистрации» или открыть `/learn?demo=1`. Демо хранится в `localStorage` под ключом `qazaqdos-learning-demo-v1`; режим действует в текущей вкладке. Личный аккаунт не использует и не импортирует демо-прогресс. Удаление данных браузера удаляет демо.

Production:

```bash
npm run build
npm run start -- --hostname 127.0.0.1 --port 3010
```

Dev использует `.next`, production — `.next-production`, поэтому одновременно запущенный dev не повреждает сборку.

## Supabase: миграции и Auth

В Supabase Dashboard → SQL Editor выполнить **по порядку**, по одному разу:

1. `supabase/migrations/202609070001_learning_mvp.sql`
2. `supabase/migrations/202609070002_learning_content.sql`

Обе миграции транзакционные. Старый `supabase/schema.sql` для нового кабинета запускать не нужно: это независимая предложенная схема исследовательского демо. Не запускать миграции повторно на уже созданных таблицах. Для новых изменений создавать следующую миграцию.

В Authentication → Providers включить Email. В URL Configuration указать Site URL и разрешённые Redirect URLs, например `http://127.0.0.1:3010/auth/callback` и production URL. Стандартный callback обменивает PKCE code на cookie-сессию. Для подтверждения email на другом устройстве можно настроить шаблон Confirm signup:

```html
<a href="{{ .SiteURL }}/auth/confirm?token_hash={{ .TokenHash }}&type=email">Confirm email</a>
```

После подтверждения доступен профиль; если таблицы не установлены, приложение показывает явную ошибку настройки базы и кнопку повторения. Никнейм не берётся из email. Service role key в приложении не используется.

Официальная документация: https://supabase.com/docs/guides/auth/server-side/creating-a-client и https://supabase.com/docs/guides/auth/passwords.

## Данные и расширение

- `lib/learning/types.ts` описывает все модели: профиль, цели, язык, курсы, разделы, уроки, упражнения, прогресс, ошибки, XP/монеты, достижения, задания дня, серии, лиги и книги.
- `lib/learning/content.ts` — источник учебного контента MVP. Добавляйте новый материал здесь, а не в JSX. Изменение контента требует пересборки приложения.
- `scripts/seed-learning.ts` экспортирует этот каталог в SQL: `npm run seed:learning`. SQL содержит insert-on-conflict-do-nothing: безопасно добавляет отсутствующие строки, но не обновляет уже существующие. После применения начальных миграций оформляйте изменения отдельной новой миграцией, не переписывайте историю.
- `lib/learning/state.ts` — единая проверка ответов, доступности, наград и изменений профиля для сервера и демо.
- `/api/learning` проверяет Supabase user, валидирует действия и пересчитывает состояние. Optimistic revision не позволяет двум вкладкам молча перезаписывать данные. При конфликте пользователь обновляет данные и повторяет действие.
- `qd_learning_states` — атомарный агрегат личного профиля и прогресса. Производные SQL views `qd_user_profiles`, `qd_lesson_progress`, `qd_user_mistakes`, `qd_*_transactions`, `qd_user_streaks`, `qd_user_quest_progress`, `qd_user_achievements`, `qd_league_participants` используют `security_invoker` и собственнический RLS. Это намеренная MVP-архитектура, а не независимые синхронизируемые таблицы прогресса.
- Каталог хранится в нормализованных `qd_courses`, `qd_sections`, `qd_lessons`, `qd_exercises`, `qd_exercise_options`, `qd_books`, `qd_book_chapters`, `qd_book_quizzes`, `qd_book_questions`, `qd_achievements`, `qd_daily_quests`, `qd_leagues`. На клиенте каталог поставляется из TypeScript; SQL-копия подготовлена для будущего редактора.
- RLS разрешает пользователю только собственный агрегат, учебный каталог доступен авторизованным пользователям только для чтения. Доступ к состояниям других пользователей и их email не выдаётся.

## Границы MVP и следующий этап

- Облачная регистрация/сохранение требует применения миграций и рабочего email-подтверждения. В этой сессии проверен доступ к Supabase и отсутствие таблицы; удалённая база не изменялась. Регистрация реального пользователя и изоляция с реальными JWT ещё требуют проверки после настройки проекта. SQL/RLS проверены локально на PGlite, а не в удалённом проекте.
- Реальный соревновательный рейтинг пока не публикуется. В MVP RLS разрешает владельцу менять свой агрегат напрямую: это обеспечивает приватность, но не защиту XP от намеренного изменения через REST. Перед запуском настоящих лиг нужны серверно-доверенный журнал наград/RPC, антифрод и конкурентные обновления на уровне операций.
- Следующий контентный этап: независимая редактура носителем языка, больше разных ситуаций и словаря, уровни A2–C1, расширение литературы, полноценный редактор администратора. Сейчас краткие задания повторяют ключевую фразу в нескольких форматах.
- Аудирование использует установленный казахский голос браузера. Если его нет, работает явно обозначенный текстовый вариант. Микрофон зависит от браузера и разрешения пользователя; распознавание текста не оценивает акцент. Нужны собственные аудиозаписи и специализированная оценка произношения.
- Открытые ответы — самооценка с образцом; свободная речь и генеративный AI не оцениваются. Следующий этап — серверный AI с педагогическими ограничениями и обработкой ошибок провайдера.
- Демо-режим и прежний исследовательский интерфейс не являются системой учёта реальных пользователей и не заменяют облачные проверки.
